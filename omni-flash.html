Fighting Style

The other three render what you describe. Omni directs what you intend — it reasons with world knowledge, fills in the detail you leave out, and then lets you refine the same clip turn by turn in plain language. Model id gemini-omni-flash-preview. The single biggest adaptation on this card: under-specify to let it improvise; over-specify to lock art direction.

✚Fighting for you

  • Conversational delta editing — “change the butterfly to a bee” on the same clip, turn by turn. Edits accumulate, they don't reset; restyles preserve motion.
  • Intent-based prompting — ~25 words of intent got model-directed coverage it invented on its own (a cinematic cut we never requested).
  • Legible on-screen text — short titles/captions render reliably; the only fighter where you can prompt type directly.
  • Speech-synced scene morphing — scene changes fire on exact spoken cue words while holding a speaker's identity from one photo ref.
  • Real cinematographic grammar — a true continuous oner through a neon night market with dolly zoom and clean subject reveal, frame-exact at 8.0s.
  • Fluid physics — milk-crown splash, Worthington rebound jet, marbled swirl: the hardest video-model task, nailed.

✖Fighting against you

  • 720p ceiling, 10s max — the finish route is a Veo upscale pass (4–8s clips → 1080p/4K).
  • No extension, no first→last interpolation, no voice editing. Do the arc in one timecoded gen, or seed a new gen from the last frame via <FIRST_FRAME>.
  • Image refs only — audio refs unsupported; video refs (≤3s) are accepted by the schema but not processed correctly.
  • Object-class replacement is shaky — ships→stingrays mostly stayed ships. Lean on material/look changes; for a true swap, put the new object in the opening prompt.
  • Storyboard = narrative reference, not style — an inked comic storyboard got re-rendered as polished semi-realistic paintings despite explicit “keep the inked look.”
  • 3 QPM, no batch + SynthID on everything — it's a directing model, not a volume model; note the watermark for client provenance.
Corner verdict
Pick it for iterative art direction, in-scene edits, on-screen text, and speech-synced morphs. The crowd was right to be skeptical of raw generation (“it still feels like Veo 3 under the hood”) — but our sweep confirms what they're circling: the control granularity is genuinely new ground. Plan it as the directing pass in a pipeline, with Kling or Seedance 2.0 handling final resolution.

The Prompting Game Plan

From our Omni prompting framework (official DeepMind guide + public-preview docs + test sweep). Two modes: GENERATE, then DIRECT.

1

The one idea — intent over instruction

Veo/Kling = render what I describe. Omni = direct what I intend. It has world knowledge, so state the goal and let it fill detail — then refine conversationally. Over-describing fights the model.

// The GENERATE template
[N] second, [16:9 | 9:16] video. [Action in a Location.] [Shot framing + camera motion.]
[Style/feel.] [Lighting source + quality.]

// Production-tested example
8 second, 16:9 video. A lone astronaut walks across an alien landscape with clear, azure
water, leaving glowing footprints. Wide establishing shot that slowly pushes in to medium.
Cinematic and majestic. Cool off-screen light, ethereal haze.

Rules: one evocative phrase per axis beats a paragraph · duration is words, aspect ratio is a real API field (response_format.aspect_ratio) · no sampling knobs — the prompt is the only control surface (negatives go in prose: “Do not show X”).

2

Detail is a control dial, not a quality lever

Validated in our test sweep: the minimal ~25-word prompt got model-directed coverage it invented; the over-specified one locked wardrobe + framing exactly and held one static shot. Both were excellent. Under-specify to let it improvise coverage; over-specify to lock art direction.

3

DIRECT — the edit grammar (the killer feature)

Edit this keeping everything the same. [ONE change.]

Swap an object     →  "Change the butterfly to a bee."
Restyle, keep motion →  "Change the ships to be made from white origami paper."
Move the camera    →  "Change the camera angle, a close-up on his shoes, quickly tilting up
                      to medium shot, then widening."
Add an action      →  "The lights of the apartments start turning on in sync with the music."
  • One change per turn — highest fidelity, isolates cause/effect, cheap to undo verbally (and quota-smart at 3 QPM).
  • “keeping everything the same” locks the rest when the change should be surgical.
  • Chain transformations — bee → swarm of fireflies → … each builds on the last; edits accumulate, they don't reset.
  • Don't re-describe what should stay — reference it; that's how consistency holds.
4

Reference patterns — image only, roles declared

<FIRST_FRAME>  → that image is the literal opening frame: "<FIRST_FRAME> a woman is walking"
<IMAGE_REF_0>, <IMAGE_REF_1>… → style/subject refs, 0-indexed, used inline

// Multi-image jobs — pin each image to a role:
[# Sources <FIRST_FRAME>@Image1] [# References <IMAGE_REF_0>@Image2]
a woman <IMAGE_REF_0> is walking.
Use Image1 as the starting frame. Use Image2 as a reference; do not use it as a literal initial frame.

Storyboard → video: attach a beat sheet and say “Follow the story exactly in order starting top left. Entire story in [N] seconds. Cinematic.” ⚠️ It reads the storyboard as beats to realize in its house style — supply the look separately.

5

The 30-second checklist

  • Mode? New video → GENERATE. Refining → DIRECT.
  • Duration in words + aspect set as a field? task set if image-driven (text_to_video | image_to_video | reference_to_video | edit)?
  • Stated intent, not a frame-by-frame script? Picked only the elements that matter (Action always; +1–3 others)?
  • One evocative phrase per axis, no synonym chains?
  • Editing → one delta + “keeping everything the same”?
  • On-screen text? Specify placement + timing + rhythm — and keep it short.
  • Needs >720p? Plan the Veo upscale pass (4–8s clips).
6

Hard constraints — bake into every prompt

Duration 3–10s (words) · Aspect 16:9|9:16 (field) · Resolution 720p, >4MB → delivery:"uri"
NOT supported: video extension · first→last interpolation · voice editing · multi-video reasoning
Multi-turn needs store=true (store=false silently kills previous_interaction_id)
Refs: image only · Quota: 3 QPM, no batch · Watermark: SynthID on all output
Editing own uploaded video: Files API {"type":"document","uri"} — works except EEA/CH/UK

⚑Field notes from our test sweep (T01–T06)

  • Native audio by default: every clip ships an AAC track — including t2v prompts that never asked for sound. QC the track on every clip; you can prompt ambience even on “silent” shots.
  • Spec adherence is exact when stated: 1280×720 · 16:9 · 5.0s · 24fps, frame-exact — duration and aspect honored from prose alone.
  • Dense on-screen text garbles — a panel with title + multiple dialogue lines produced gibberish; the short “OVER THE CRAGS” rendered perfectly. Keep captions terse.
  • Color is the reliable character anchor — cape color held across beats while headgear/armor freelanced (even flipped). Lock per-character details separately.
  • Lip-sync works on stylized characters — a claymation robot delivered its line with good mouth animation; verify words offline with whisper.cpp before a human listen.
