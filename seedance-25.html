Fighting Style

The only model on the card that takes text + image + video + audio in one call and then keeps working after the bell — editing, extending, bridging. It's not a straight upgrade from 2.0; it's a different fighter for a different job.

Reference load50 refs
Narrative length30s + extension
In-place editingTimestamp-scoped
Delivery resolution720p max
Cost efficiency~1.5× 2.0
Style adherenceWeakest layer

✚Fighting for you

  • 50 reference materials with per-material role and exclusion control — nothing else takes this many.
  • 30-second narrative in one generation via stages + declared end states — no stitching 15s halves.
  • Real editing: scoped subject replacement, background swap, relight, audio-only edits, language change with timing preserved.
  • Forward and backward extension plus generated seamless transitions between clips.
  • Native audio in 10+ languages with mid-clip switching and regional-accent pinning.
  • Previz → final: renders grey blockouts into finished footage (coarse/fine blockout modes).

✖Fighting against you

  • 720p ceiling — a regression from 2.0 (4K) and the one hard blocker for broadcast/CTV.
  • ~1.5× the cost of 2.0 with no Fast/Mini tier — high-volume work gets priced out.
  • No seed control in the UI — budget more than one roll per test.
  • Style adherence is materially weaker than structural adherence (a 90s-sitcom brief nailed the structure, ignored the era look).
  • Timestamps are time budgets, not frame-accurate edit points.
  • Marketing says “4K & 30s”; the parameter table says 480p/720p only. We believe the table.
Corner verdict
Pick it for multi-character spots, 30s one-pass narratives, and editing a finished clip. Do not pick it for final delivery above 720p — run the two-model pipeline: 2.5 for duration and editing, Seedance 2.0 for the 1080p/4K finish. Any plan that ignores the resolution regression is wrong.

The Prompting Game Plan

Distilled from the official ModelArk guide (Aug 7, 2026) + our prompting framework + 12 production generations. This is how you get the best out of it.

1

The core formula — then stop

Everything after Action is optional. Never put generation parameters in the prompt — resolution, ratio and duration are set on the page/API.

Subject + Action/Event + Scene & Environment + Visual Style + Camera/Cut + Audio

<Subject> performs <primary action or event> in <scene and environment>.
The visuals feature <visual style>.
Use <shot size, camera angle, camera movement, or cuts>.
Audio includes <dialogue, ambience, sound effects, or music>.
2

References: state what to use AND what NOT to use

The single most important rule. Bind every subject individually — “@Images 1 through 4 define four characters respectively” is meaningless to the model.

@Image 1 defines the ceramic artist's facial features, hairstyle, and dark green apron.
         Do not use the image background.
@Image 2 defines the workbench, window placement, and morning light.
         Do not use the people in the image.
@Video 1 defines the pacing of throwing clay, lifting the cup, placing it down.
         Do not use the person's identity, clothing, or scene from the video.

Recommended load: 1–8 distinct subjects across subject images · 1–5 distinct subjects in video refs (5–10s each) · only task-relevant audio. Stretch ranges (9–12) exist but stability drops. Over five subjects needing multiple views → separate images per view, never a collage.

3

30s narratives: stages first, timestamps for precision

Each stage gets one primary state change and a declared end state — what is directly visible when the stage finishes. That's the continuity mechanism.

[Generation Goal]
Generate a <video type>. Central subject <subject>, primary event <story summary>.

[Stage 1]
Initial state: <characters, props, scene>.
Primary event: <one primary action>.
End state: <positions, prop ownership, visible scene state>.

[Stage 2]
Continue from the previous stage: <what must remain unchanged>.
Primary event: <one primary action>.
End state: <observable state>.

[Maintain Consistency]
Keep <identity, character count, clothing, prop ownership, spatial direction, audio> consistent.

Use timestamps only for critical control — a handoff, an entrance/exit, a transition. Ranges must be consecutive and non-overlapping; they're time budgets, not edit points.

4

Editing: source is the sole master, then scope the change

[Edit Goal]        Edit @Video 1. Within <whole video | time range>, <add|remove|replace|adjust> <target>.
[Source Video Role] @Video 1 is the sole editing master. It defines <characters, scene, actions,
                    composition, camera movement, occlusion, audio, event order>.
[Edit Scope]       Modify only <object, region, time range, or audio category>.
[Content to Preserve] Keep <what must not change> from @Video 1.

Subject replacement adds a Timeline Inheritance clause: the target inherits every appearance, motion, occlusion and exit of the original. Audio editing is granular — dialogue, language, voice, BGM and SFX are separately editable.

5

The special syntax (memorize it)

Music       →  ( Soft, rhythmic piano plays in the background )
Sound FX    →  <A bell rings in the distance>
Dialogue    →  {Hello, welcome back.}
Subtitles   →  【Chapter One: Departure】

// Dialogue language reinforcement — pins accent + delivery:
Dialogue language: authentic Los Angeles English. The young man says in natural
Los Angeles vernacular: {No way, you actually made it.}
6

Cinematography + emotion, the 2.5 way

Standard terms work directly (push in, orbit, dolly out, low angle…). Popular techniques need one extra clause: which subject, where the move starts and ends. Uncommon terms: keep the term AND translate it into observable change (“Rack focus: shift focus smoothly from the leaves in the foreground to the person behind…”). Emotion words set direction; 2–4 observable cues control the performance — eyes, brows, mouth, breathing, hands.

⚑Anti-patterns (learned the expensive way)

  • Grouped reference bindings — “images 1–4 define four characters respectively.” Bind individually, always.
  • Demanding frequency — “three actions in one second” breaks the timeline. One primary event per stage.
  • Restating motion a reference video already carries — state only which attributes to inherit; restating conflicts with the ref.
  • Two ideas in one beat — an orbit-plus-time-reverse in 5s delivered only the orbit. One idea per beat.
  • Promising reserved safe zones — “keep the upper third clean” held in a wide and failed in a tight shot, same week. Never promise what you haven't seen.
  • Trusting style adjectives — specify what happens; treat the look as a request, not a command.

Field Notes — What the Docs Don't Say

From our production generations, Jul 31 – Aug 7, 2026 (BytePlus Research). The official guide doesn't tell you any of this.

⚠Gotchas that will save you

  • File metadata lies about frame rate. r_frame_rate reports 60; the real rate is 24. Check avg_frame_rate + frame count — anyone spot-checking will misread it.
  • Extension re-encodes 24 → 30fps and returns source + extension as one clip. Don't extend anything already signed off; budget a conform pass.
  • Unrequested brand marks appear. A logo supplied for an end card turned up on wardrobe and a coffee mug.
  • Duration isn't promise-able yet. One 15-second ask returned 5.06s.

★Where it quietly got good

  • On-screen type is now often reliable. A brand wordmark rendered correctly at four different scales in one spot; a product label survived a full push-in. Verify, but stop pre-rendering by default.
  • A written timeline is honoured as a timeline — stage beats land where you put them (within the time-budget tolerance).
  • Reference casting holds across an extension join — identity survives the boundary frame.
